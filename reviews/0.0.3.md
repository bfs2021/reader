# 0.0.3 release review

Range: `v0.0.2..7394319` on `milestone/0.0.3` (68 commits: main since v0.0.2, and this week's 0.0.3 issues).
597 tests and lint passed at 7394319; after the fixes below, 607 do.

## How this review was done

Four reviewers, one per dimension in #79's checklist, each working read-only against the same commit. The reviewers were Claude agents, each briefed with the same instructions (the method is in [REVIEWING.md](../REVIEWING.md)); the maintainer chose what to fix, file and set aside from their merged lists.

- **Technical debt:** duplication, dead code, workarounds.
- **Quality:** tests missing for what changed, lint, naming, docs and README.
- **Correctness:** bugs, especially where this week's changes meet (they were built one after another).
- **Accessibility:** WCAG 2.2 AA. axe in light, dark, more contrast and forced colours; the accessibility tree; a keyboard trace through presenting; and a log of everything the deck's live region said.

Each reviewer was given the week's work report (every issue's own flags), every open issue, and the private
security notes, so as not to report what's already known. Each finding was reproduced where it could be, and
marked when it was read only. Each reviewer also wrote down what it looked at and decided was *not* a finding.

Then the four lists were merged: duplicates folded together (four findings were found by two reviewers each),
and each finding given a milestone, by three questions:

1. **Is it new in this milestone, and small?** Then fix it before the tag, as a polish of the issue that
   introduced it. A release shouldn't ship a regression of its own making.
2. **Does it matter for the talk on 2026-11-22?** The deck and the speaker view are what 0.0.3 is for.
3. **Otherwise, where does it fit?** The milestone whose theme it belongs to, or an existing issue that
   already covers the same code.

No security findings.

## Set aside, and why

### Already covered

- **Stage frame titled "Slide N of M", not the deck's name:** #145, fixed by PR #159.
- **marks importing from asides (`ownColor`, `inFamily`):** #141.
- **version-app.test.js copying theme-app.test.js's setup:** #161, #162.
- **`present()` resetting the text size untested:** the #136 polish added that test.
- **#111's export palette bullet:** already done in 7a874f1. The suggested `@media screen` scope would change how a dark page prints.
- **#111's `escapeLineStart` export:** tools/gutenberg moved to reader-authors.
- **#111's storage try/catch and placeholder table:** both done. Only state.js keeps a try/catch, and every placeholder comes from the table.

### Deliberate, or a browser's limit

- **#142's blur + setTimeout gate:** in Chrome, `document.hasFocus()` is still true during `focusout`. Documented and tested.
- **theme.js and views.js keep their own storage try/catch:** they're plain scripts loaded outside the app's modules.
- **`escapeAttr` kept as an alias of `escapeHtml`:** harmless. The `>` question is a private security note.
- **Tab swallowed in the overview:** a roving listbox. Esc is shown and works, so it isn't a keyboard trap.
- **`#deck` shows no focus ring:** it's the full-screen container, not a control. Tab moves a visible ring into the slide.
- **Tab on a slide with nothing to reach says nothing:** as the platform does.
- **⌘+ in the speaker window zooms that window:** the room's size is set from the deck. Zooming the speaker page is fine for 1.4.4.
- **Keys in the speaker view drive the room's open overview:** either window can drive the deck.
- **The deck's foot says ⌘ on Windows and Linux too:** the whole app does, and Ctrl works.
- **Going back onto a slide says its title, with the step count:** what #165 asked for.
- **`sized()` setting the scale directly:** a deliberate measure-then-restore.

### Checked and fine

- **docker.yml's newest-tag step:** sees the tag release.yml just pushed, drops pre-releases, sorts v0.0.10 after v0.0.9. It reads tags without credentials, which needs the repo to stay public.
- **`.deck .gm-doc pre` zoom:** can't undo the fit, since slides always wrap their body.
- **⌘+ "never smaller":** holds to within the fit's 0.01 search step.
- **Overview thumbnails messaging the app:** main.js and fit.js ignore them.
- **#111's picks folded into views.js:** keys, messages and limits kept.
- **Author colours in forced colours:** the system's colours win, and chips are covered.
- **Letters typed into an input on a slide:** fields aren't inputs on a slide since #144, and puzzles take their keys.
- **Overview listeners never removed:** `create()` runs once per page.
- **The overview cleaned up a duplication:** `paging()` is now one function.
- **A transition replacing one `say` with another:** a stale reply is always dropped.
- **Lint:** clean, with no new eslint-disable comments.
- **New names** (`typable`, `fillable`, `owns`, `sizeKey`, `scaleTo`): read clearly.
- **README:** makes no claims this release changes.
- **Legend chips' contrast:** axe couldn't compute it (overlap). #135's measurements show 5.9-14.9:1.

### Too small to file, or predates this range

- **⌘+ at 200% repeats "Text 200%":** harmless.
- **A labelled date's name is its label, not the day:** predates the range, and sighted readers see the label too.
- **A blank date on a slide reads "pick a date":** the visible wording.
- **Esc from the deck focuses the editor:** unchanged since v0.0.2, and a sensible "back to editing".
- **`closeDeck()` with the overview open:** rare, and focus lands sensibly.
- **`#deckSays` could keep old text if the stage never answers:** rare.
- **axe best-practice hits** (masthead banner, no h1 in the app shell, speaker overview outside a landmark): predate the range, or add nothing while the rest is inert.
- **Focus ring sub-pixel under ⌘+:** about 1px on screen.
- **presenting.md's overview text doesn't mention Space:** matches the on-screen hint.
- **qa.test.js stricter than it needs to be:** not debt.
- **The speaker hint "O overview" untested:** a static string.
